# DocSync

기획안·회의록·긴 글에서 개발 가이드에 반영할 내용을 추출하고, 프로젝트의 Markdown 문서에 항목 단위로 검토·수정·반영하는 설치형 데스크톱 앱입니다.

- 별도 서버·DB 없음. 사용자 PC에서 실행
- AI는 사용자 API 키(Anthropic, OpenAI, Gemini, Groq, OpenRouter)로 호출
- 마지막 프로젝트, 프로젝트별 반영 범위, 제공자별 API 키는 앱을 다시 켜도 유지 (`%APPDATA%/docsync/settings.json`, 키는 OS 보안 저장소로 암호화)
- 대화·추출 항목·되돌리기 정보 같은 작업 데이터는 메모리에만 있고 앱 종료 시 삭제
- 실제 반영한 파일 변경만 디스크에 남음

## 실행

앱은 **테스트 ON**으로 시작하며 샘플 프로젝트를 바로 엽니다. 이 프로젝트에서는 AI API를 호출하지 않습니다. **테스트 OFF**로 바꾸면 이전에 작업하던 실제 프로젝트로 돌아갑니다. 다시 ON으로 바꿔도 양쪽 프로젝트의 현재 대화·항목·되돌리기 상태를 앱 실행 중에는 각각 유지합니다. 샘플 프로젝트는 실제 프로젝트의 마지막 경로 설정을 덮어쓰지 않습니다.

샘플 프로젝트에서 **예시 회의록 입력** → **보내기**를 누르면 회원가입 전환 회의록에서 5개 항목이 생성됩니다. 결정된 항목 하나가 제품·API·화면·DB·QA 등 여러 Markdown 파일을 함께 수정하는 모습을 문서별 diff로 볼 수 있습니다. 미결 사항은 기본 반영 대상에서 제외됩니다. 파일별 결정·반영·되돌리기는 실제 샘플 파일에 적용됩니다. 샘플 파일은 앱 데이터 폴더의 `sample-project-v2`에 생성됩니다. 반영 후 **새 샘플 시작**을 누르면 변경을 덮어쓰지 않고 새 번호의 샘플 폴더를 만듭니다.

샘플 프로젝트에 다른 자료를 보내면 문장을 나누어 간단한 예시 변경안을 만듭니다. 이는 AI 분석 결과가 아니며 화면에서도 **테스트 응답**으로 표시합니다. 실제 프로젝트에서는 기존 AI API 흐름을 사용하며 API 키와 사용량에 따른 요금이 필요할 수 있습니다.

Node.js 20 이상이 필요합니다.

```bash
npm install
npm run dev        # 개발 모드 실행
npm test           # 반영·되돌리기·링크 수정 엔진 테스트
npm run typecheck
```

## 설치 파일 만들기

```bash
npm run dist:win   # Windows → release/DocSync Setup x.y.z.exe
npm run dist:mac   # macOS → release/DocSync-x.y.z.dmg (macOS에서 실행)
```

각 OS용 설치 파일은 그 OS에서 빌드합니다. 코드 서명을 하지 않으면 Windows SmartScreen, macOS Gatekeeper 경고가 나옵니다(내부 사용은 그대로 실행 가능).

## 사용 흐름

1. **폴더 열기** → 프로젝트 연결. `docs/` 폴더가 있으면 자동으로 반영 범위로 지정 (트리의 ◎ 버튼으로 변경)
2. 상단 **API 키** → 제공자 선택, 키 입력, 모델 선택
3. 회의록을 붙여넣거나 클립 버튼으로 .md·.txt 파일 첨부 → 항목 추출·문서 매핑·변경안 생성
4. 항목 선택 → 매핑 파일 강조, 파일별 diff 확인. 파일마다 **기존 유지 / 제안 채택 / 보류** 선택 (diff를 직접 고친 뒤 채택하면 고친 내용으로 반영)
5. 모든 파일을 확인하면 **반영** (또는 반영 대기 항목 모두 반영). 채택한 파일만 수정되고, 반영한 항목은 언제든 항목 단위로 **되돌리기**
6. 추가 자료를 보내면 기존 항목과 병합 (같은 내용 / 구체화 / 충돌 / 새 항목)
7. "인증 문서를 docs/security/로 옮겨줘" 같은 요청 → 이동·상대 링크 수정 변경안

## 구조

```
src/
  shared/          main·renderer 공용 타입, 근거 위치·형광펜 구간 계산
  main/
    index.ts       창, IPC, 종료 안내, 파일 변경 감지(chokidar)
    session.ts     작업 상태(메모리)와 모든 동작
    core/engine.ts 반영·되돌리기 엔진 (계산 후 쓰기, 실패 시 복구)
    core/links.ts  Markdown 링크 분석, 이동 시 링크 수정안
    core/projectFs.ts  프로젝트 폴더 접근 (루트 밖 차단, 임시 파일 후 교체)
    ai/client.ts   Anthropic·OpenAI 호출, JSON 스키마 강제 + zod 검증
    ai/pipeline.ts 프롬프트 (추출·병합 / 요청 분류 / 항목 재생성)
  preload/         화면에 허용한 API만 노출 (contextBridge)
  renderer/        React 화면 (파일 트리 / 대화·항목 / diff·원문·편집기)
tests/             엔진·링크·근거 위치 테스트
```

## 변경 모델

모든 변경은 "현재 파일의 `oldText`(파일 안에서 유일)를 `newText`로 치환"으로 표현합니다.

- 반영 직전에 기준 문구를 다시 확인하고, 없거나 여러 곳이면 반영하지 않고 **재검토 필요**로 전환
- 한 항목의 여러 파일은 메모리에서 모두 계산한 뒤 쓰고, 중간 실패 시 앞서 쓴 파일을 복구
- 앞선 반영으로 다른 항목의 기준 문구가 사라지면 그 항목을 자동으로 재검토로 전환 → "변경안 다시 계산"
- 되돌리기: 파일이 반영 직후 그대로면 통째로 복구, 다른 곳이 바뀌었으면 이 항목의 치환만 역으로 적용. 같은 구간을 나중에 고친 항목이 있으면 그 항목부터 되돌리도록 안내
